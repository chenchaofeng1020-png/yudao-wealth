## 1. 概述

### 1.1 背景

运营需要定期组织线下活动（投资沙龙、行业分享会、闭门研讨会等）邀请客户到场参加，客户报名需要登记个人信息并支付报名费。目前活动报名依托小鹅通的活动模块承接，报名数据与费用沉淀在第三方平台，与星球的会员体系、商城订单相互割裂，名单查看与运营管理需要在两个系统之间来回切换。

本文档描述「活动模块」的完整业务：管理后台负责活动的创建、发布与报名名单管理；C 端在星球移动端内提供活动浏览、报名与支付能力。

### 1.2 目标

- 活动报名统一沉淀到本系统：报名数据、报名费与星球的会员体系、商城订单打通，运营在一个系统内完成活动的组织与名单管理。
- 运营可以在后台完成活动的全生命周期管理：新建 → 发布 → 报名 → 下架/结束 → 删除。
- 客户在星球移动端「活动中心」浏览活动、选择票种、填写报名信息并完成支付。
- 报名费支付复用商城订单链路：活动 + 票种本身即商品，报名支付直接生成商城订单，订单统一在商城订单模块管理。
- 报名名单实时更新，运营可在后台按活动查看、取消报名、导出 Excel。

### 1.3 功能模块范围

| 端 | 模块 | 功能板块 | 功能点描述 |
|---|---|---|---|
| 管理后台 | 活动管理 | 活动列表 | 关键词与状态筛选、名额进度、状态标签、操作按钮按状态展示 |
| 管理后台 | 活动管理 | 新建/编辑活动 | 基本信息分组、票务设置（多票种）、报名信息设置（自定义组件） |
| 管理后台 | 活动管理 | 状态流转 | 报名中/已结束/已下架，上架、下架、删除 |
| 管理后台 | 活动管理 | 分享 | 活动链接复制、二维码下载 |
| 管理后台 | 活动管理 | 活动详情与报名名单 | 活动信息卡片、报名名单动态列、取消报名、导出 Excel |
| 管理后台 | 活动管理 | 订单与退款 | 票种即商品、报名支付生成商城订单、退款联动报名记录 |
| C 端 | 活动中心 | 活动列表 | 筛选页签、活动卡片、空状态 |

### 1.4 名词和缩略语

| 术语 | 说明 |
|---|---|
| 票种 | 活动下的一个可售票类，包含票种名称、价格、票数、票种说明；一个活动可配置多个票种 |
| 席位/名额 | 一张票对应一个活动名额，活动总名额为全部票种票数之和 |
| 报名记录 | 一张票对应一条报名记录，记录该席位填写的报名信息、支付金额与状态 |
| 有效报名 | 状态为「已报名」的记录；已取消的记录不占用席位 |
| 参会人 | 一张票对应的到场人，填写内容为报名信息设置中各组件的值 |
| 票种即商品 | 活动 + 票种本身作为商品身份参与下单，无需在商城商品中心单独建档；报名支付统一生成商城订单，复用商城订单管理能力 |

## 2. 整体业务流程

```
【管理后台】                              【C 端（星球移动端 H5）】
新建活动
（基本信息/票务设置/报名信息设置）
   │  保存并发布
   ▼
【报名中】── 票种即商品，报名支付统一生成商城订单
   │
   │  分享链接 + 二维码 ──► 运营发给客户
   │                              │
   │                              ▼
   │                      我的 → 活动中心
   │                      浏览活动列表 / 详情
   │                              │ 点击「立即报名」
   │                              ▼
   │                      选择票种与参会人数
   │                      填写报名信息（每张票一份）
   │                              │ 确认并前往支付
   │                              ▼
   │                      商城订单支付（微信支付）
   │                              │ 支付成功
   ▼                              ▼
报名名单更新 ◄───────────── 报名记录生效、占用席位
（查看 / 取消报名 / 导出 Excel）
   │
   ├─ 报名截止时间到达 ──► 【已结束】，C 端报名入口关闭
   ├─ 手动下架 ──► 【已下架】，C 端不再展示
   └─ 后台取消报名 / 商城退款成功 ──► 席位释放、记录标记已取消·已退款
```

## 3. 管理后台：活动管理

入口：管理后台「内容中心 > 活动管理」。页面采用后台标准表格风格（斑马纹、状态标签、操作列固定在右侧）。

### 3.1 活动列表

- 筛选区：活动名称关键词（模糊搜索）+ 状态下拉（全部 / 报名中 / 已结束 / 已下架，默认「全部」）；「重置」恢复默认筛选。
- 列表按创建时间倒序排列，每页默认 20 条；只要列表有数据就显示分页器，空列表不显示。
- 每行展示：活动名称（主行为名称、副行为活动地点）、报名费、名额进度、状态标签、活动时间（开始 ~ 结束两行）、报名截止时间、操作按钮。
- 报名费：单一票种显示该票种价格；多票种显示最低票价并加「起」字。
- 名额进度：有效报名数 / 总名额；满员时名额进度旁显示「已满员」标识。
- 状态标签配色：报名中（绿）、已结束（橙）、已下架（红）。
- 操作按钮按活动状态展示，规则见 3.3 状态流转。

### 3.2 新建 / 编辑活动

点击「新建活动」或列表行内「编辑」进入二级页面。页面顶部工具栏左侧为「返回列表」按钮与页面标题（新建活动 / 编辑活动），右侧为保存按钮。

表单按三个分组组织：基本信息、票务设置、报名信息设置。

**原型示意**：

```

|  基本信息                                                                    |

|  [手机号]   [手机号______]                                  [x] 必填        |

|  [单项选择] [从事行业_____]                                 [x] 必填 [删除] |
|    └ 选项  1. [银行/证券________] [删除]                                    |
|            2. [保险_____________] [删除]                                    |
|            3. [基金/资管_________] [删除]                                   |
|            4. [其他_____________] [删除]                                    |
|            [+ 添加选项]                                                     |
|  [+ 添加组件 v]   （单行文本 / 多行文本 / 单项选择 / 多项选择）              |
```

**(1) 字段说明**

基本信息：

a. 活动名称：必填，文本，最多 50 字。

b. 活动地点：必填，文本，最多 100 字，展示于 C 端活动详情页。

c. 活动时间：开始时间与结束时间必填，精确到分，结束时间必须晚于开始时间。

d. 报名截止时间：必填，须早于活动结束时间，可以晚于活动开始时间（即活动开始后仍可报名，由运营自行把握）；截止后 C 端自动关闭报名入口。

e. 活动海报：必填，单图上传，支持 jpg/png，建议尺寸 750×560；展示于 C 端活动详情页顶部与后台详情页信息卡片。

f. 活动详情：必填，富文本编辑器，支持图文混排与图片上传，展示于 C 端活动详情页。

票务设置：

a. 可添加多个票种，每个票种包含：票种名称（必填，最多 20 字）、价格（必填，大于 0 的金额，保留两位小数）、票数（必填，大于 0 的整数）、票种说明（选填，最多 200 字）。

b. 票种可删除，已有有效报名的票种不可删除；编辑「报名中」活动时票种价格锁定不可修改，页面提示「报名中不可修改票种价格，如需调价请先下架」。

c. 票种本身即商品：无需在商城商品中心单独建档，票种的名称、价格即订单中的商品信息，订单与退款规则见 3.6。

报名信息设置：

a. 默认提供姓名、手机号两个固定组件，默认必填；固定组件的名称不可修改、不可删除。

b. 可添加四类自定义组件：单行文本、多行文本、单项选择、多项选择；自定义组件可修改名称（最多 20 字）、可设置是否必填、可删除。

c. 单项选择与多项选择的选项逐项添加：每个选项独立一行填写，可添加、删除（至少保留一项），有效选项（非空）不足 2 项时不可提交。

d. 报名时客户每买一张票需填写一份报名信息，购买多张票需填写多份；同一活动的全部票种使用同一份报名信息配置。

**(2) 保存逻辑**

- 按钮随编辑场景变化：

| 场景 | 保存按钮 |
|---|---|
| 新建活动 | 「保存并发布」 |
| 编辑已下架 / 报名中 / 已结束活动 | 「保存修改」 |

- 「保存并发布」（新建）：校验全部必填项；保存后活动直接进入「报名中」并生成分享链接，票种即可报名支付。报名截止时间已过不允许发布，点击时提示「报名截止时间已过，无法发布，请先调整报名截止时间」。
- 编辑「已下架」活动：全部字段可修改，保存后保持「已下架」，重新上架后修改对 C 端生效。
- 编辑「报名中」活动：活动名称、活动时间、活动地点、海报、活动详情、票数、报名信息设置可修改；票种价格锁定；各票种票数不可低于该票种已产生的有效报名数。
- 编辑「已结束」活动：仅活动详情可修改，其余字段置灰。
- 「保存修改」保存后实时同步 C 端。

### 3.3 状态流转

```
            新建活动 · 保存并发布
                     │
                     ▼
                +----------+ ── 报名截止时间到(自动) ──► +----------+
                |  报名中  |                              |  已结束  |
                +----------+                              +----------+
                   │           ▲
                   │ 手动下架  │ 上架（报名截止时间未过）
                   ▼           │
                +----------+───┘
                |  已下架  |
                +----------+
```

| 状态 | 进入方式 | C 端可见性 | 列表操作按钮 |
|---|---|---|---|
| 报名中 | 新建保存并发布 / 上架 | 列表与详情可访问、可报名 | 详情、分享、编辑、下架 |
| 已结束 | 报名截止时间到达自动流转 | 详情可访问、报名入口关闭 | 详情、编辑（仅活动详情） |
| 已下架 | 手动下架 | 不再展示 | 详情、编辑、上架、删除（无报名记录时） |

- 「下架」：仅报名中状态展示；下架后 C 端不再展示该活动，报名名单、订单与退款状态全部保留；下架无需二次确认。
- 「上架」：仅已下架状态展示；报名截止时间已过时按钮置灰，悬浮提示「报名截止时间已过，无法上架」；上架后恢复「报名中」，报名与支付链路不变。
- 「删除」：仅已下架且从未产生报名记录（含已取消）的活动可删除；点击需二次确认「删除后活动不可恢复，确认删除？」；产生过报名记录的活动不显示删除按钮，只能下架。
- 已结束为系统自动流转，无需人工操作；已结束活动在 C 端进入「往期回顾」。

- 信息卡片下方为报名名单区：页签「全部(N) / 已报名(N) / 已取消(N)」带实时计数，右侧「导出 Excel」按钮。
- 名单固定列依次为：报名用户（提交报名的登录账号）、会员手机号（登录账号手机号，明文展示）、票种、报名时间（支付成功时间）、价格（该张票实付金额）、状态、订单号。
- 动态列：订单号之后按当前活动配置的报名组件逐一生成独立列，列名即组件名称，取值为该张票填写的内容；姓名、手机号组件同样生成独立列。理财师为运营添加的报名组件，其列固定紧跟手机号列之后；活动未配置手机号组件时排在报名信息列末尾。
- 一张票对应一条名单记录；同一订单购买多张票时拆分为多条记录，订单号与报名时间相同。
- 状态列：已报名（绿点）；已取消（灰点），旁附「已退款」标记。
- 取消报名：仅后台操作，已报名记录的行内显示「取消报名」按钮（已取消记录显示「-」），点击弹出确认框；确认后席位立即释放、实付金额原路退回，记录状态变为「已取消」并标记「已退款」，C 端报名结果同步更新，无审核流程。
- 导出 Excel：导出当前页签的结果；表头与报名名单列表一致——固定列为报名用户、会员手机号、票种、报名时间、价格、状态、订单号，其后按报名组件生成动态列（列名即组件名称，理财师列紧跟手机号组件后，活动未配置手机号组件时排在报名信息末尾）；一份票一行记录；文件命名「活动名称-报名名单-导出日期」。

### 3.6 订单与退款

- 票种即商品：活动 + 票种本身作为商品身份参与下单，不在商城商品中心单独建档，也不进入商城货架售卖；活动票种仅通过活动报名入口产生订单，避免商城与活动两个入口同时售卖导致名额失控。
- 订单：客户报名支付成功后统一生成商城订单，订单在商城订单管理中查看与管理；订单保存下单时的商品快照（活动名称、票种名称、单价、数量），后续票种调整不影响已生成订单的金额。
- 退款：退款在商城订单管理中发起（后台「取消报名」同样触发原路退款）。退款发起后订单进入「退款中」，对应报名记录维持「已报名」、席位继续占用；退款成功后报名记录自动变为「已取消」，席位同步释放，名额进度与 C 端席位余量实时更新；退款失败则订单与报名记录保持原状态。已取消记录不计入有效报名与名额进度。

## 5. 名额与票务规则

- 席位按票计：一张票对应一个席位与一条报名记录，购买 N 张票占用 N 个席位。
- 活动总名额 = 全部票种票数之和；票种剩余席位 = 该票种票数 − 该票种有效报名数。
- 有效报名 = 已支付且未退款的报名记录；有效报名数达到总名额即满员，报名入口关闭。
- 报名资格双重校验：报名截止时间未到且有剩余席位，任一不满足即关闭报名入口。
- 报名次数：同一账号对同一活动限报名一次，多席位在报名时通过参会人数一次提交。
- 并发边界：最后剩余席位被多人同时支付时，以支付成功顺序为准；支付成功时席位已满的订单自动全额退款，对应报名不生效。
